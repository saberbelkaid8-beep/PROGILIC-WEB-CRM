# نظام إدارة الشركات والموظفين والأقسام والصلاحيات (PROGILIC Multi-Tenant CRM & RBAC)

نظام سحابي عام متعدد الشركات والمؤسسات (Multi-Tenant B2B SaaS). يتيح لأي شركة أو مؤسسة التسجيل بحسابها الخاص، حيث يمتلك مدير الشركة (Gérant) الصلاحيات الكاملة والمتفوقة على كل شيء، مع إمكانية إنشاء حسابات موظفي شركته وتحديد أقسامهم ومسؤوليهم المباشرين ومهامهم وصلاحياتهم الدقيقة، وبوابة دخول مرنة للموظفين عبر اسم المستخدم وكلمة المرور الخاصة بكل شركة.

---

> [!IMPORTANT]
> **التحديث الجوهري بناءً على توجيهاتكم الأخيرة (نظام عام لكل المؤسسات):**
> 1. **التعميم وإلغاء الارتباط بحساب واحد**: النظام أصبح عاماً (Universal Multi-Tenant)؛ لم يعد مقتصراً على حساب محدد، بل يمكن لأي مؤسسة أو شركة في الجزائر أو خارجها إنشاء حسابها والعمل بنظامها المستقل.
> 2. **هرمية الشركة والمدير (Gérant Super-Admin)**:
>    - حساب المؤسسة/المدير هو الحساب السيادي (Root / Master Account) الذي يملك السيطرة الشاملة والتفوق على كافة العمليات والبيانات.
>    - المدير هو من ينشئ حسابات موظفي شركته، ويمنح أو يعدل الصلاحيات في أي وقت، ولا يملك أي موظف حق تعديل صلاحيات المدير أو تجاوزه.
> 3. **عزل البيانات الصارم (Tenant Data Isolation)**:
>    - بيانات كل مؤسسة (العملاء، البرامج، المشاكل، المتطلبات، الموظفون، الأقسام، المهام) معزولة تماماً في قاعدة بيانات Firestore ومحمية برمجياً وقانونياً عبر قواعد الأمان.
> 4. **بوابة تسجيل الدخول الذكية**:
>    - **دخول المؤسسة / المدير**: عبر Google أو البريد الإلكتروني للشركة لإنشاء فضاء عمل جديد أو إدارته.
>    - **دخول موظفي المؤسسة**: عبر اسم المستخدم وكلمة المرور الخاصة بموظفي تلك المؤسسة مع التوجيه التلقائي لفضاء شركتهم.

## 1. نظرة عامة والمفهوم الأساسي (Overview & Core Concept)

### لمن صُمم هذا النظام؟
- **لأي شركة أو مؤسسة تجارية أو برمجية أو صناعية** ترغب في إدارة علاقات العملاء وفرق العمل.
- كل شركة تحصل على فضاء عمل رقمي مستقل (Dedicated Company Workspace) بمجرد تسجيل حساب المدير.

### المكونات الرئيسية للمنظومة
1. **فضاء الشركة المستقل (Company Workspace)**:
   - يحمل اسم الشركة، شعارها، بياناتها، وقاعدة بيانات عملائها وتراخيصها المستقلة.
2. **الإدارة العليا للمدير (Gérant Super-Admin Console)**:
   - لوحة تحكم حصرية للمدير لإدارة الهيكل الوظيفي:
     * إضافة، تعديل، تجميد أو حذف حسابات الموظفين.
     * ضبط مصفوفة الصلاحيات الدقيقة لكل موظف (قراءة، تعديل، حجب).
     * تعيين الأقسام الإدارية والمسؤولين المباشرين.
     * إسناد المهام الاستراتيجية والتشغيلية ومتابعة مؤشرات الإنجاز.
3. **الأقسام التشغيلية المعيارية (Departements Framework)**:
   - **قسم ما قبل البيع (Service Pré-vente)**: استقطاب العملاء، التعريف بالبرامج، تقديم العروض التجريبية والتواصل المبدئي.
   - **القسم التجاري والمبيعات (Service Commercial)**: إدارة الصفقات، التفاوض، عقود البيع، متابعة العملاء النشطين والمحتملين.
   - **قسم الدعم وما بعد البيع (SAV & Support Technique)**: متابعة التثبيتات على الأجهزة، معالجة المشاكل التقنية والتذاكر.
   - **قسم التطوير والبرمجة (Développement & Technique)**: تلبية متطلبات ومقترحات العملاء، تطوير التحديثات والمنصات.
   - **قسم المحاسبة والمالية (Comptabilité & Finance)**: الفواتير، اشتراكات البرامج والتراخيص، ومتابعة الدفعات.
   - **الإدارة العامة (Direction Générale / Gérance)**: الإشراف الكامل والمطلق على سائر الأقسام والعمليات.
4. **حسابات الموظفين وبوابة الدخول (Employee Portal)**:
   - كل موظف يدخل باسم مستخدم فريد وكلمة مرور يحددها المدير.
   - يرى الموظف الواجهات والأزرار المسموح له بها فقط بناءً على الصلاحيات وقسمه ومسؤوله المباشر.

## 2. تجربة المستخدم والتصميم البصري (UX & Visual Design)

### مسار رحلة العمل (Workflows)

```
                       ┌───────────────────────────────┐
                       │    بوابة الدخول الرئيسية      │
                       │     (Universal Gateway)       │
                       └───────────────┬───────────────┘
                                       │
                 ┌─────────────────────┴─────────────────────┐
                 ▼                                           ▼
      [تسجيل / دخول شركة جديدة]                     [تسجيل دخول الموظف]
       حساب Google أو إيميل المدير                     اسم المستخدم + كلمة المرور
                 │                                           │
                 ▼                                           ▼
       فضاء المؤسسة الكامل                          فضاء الموظف المقيد بالصلاحيات
    (Company Master Workspace)                      (Scoped Employee Workspace)
                 │                                           │
  ┌──────────────┴──────────────┐                            │
  ▼                             ▼                            ▼
[إدارة الأقسام والموظفين]   [كافة الصلاحيات]          [تنفيذ مهام القسم فقط]
- إضافة/تعديل الموظفين     - عملاء، برامج، دعم        - عملاء مصرح بهم
- ضبط الصلاحيات بدقة        - مبيعات، مالية، تقارير    - مشاكل تقنية مكلف بها
- تعيين المسؤول المباشر     - تحكم غير محدود           - مهام من المسؤول المباشر
```

### واجهة إدارة الموظفين والأقسام (Équipe & Permissions)
- **جدول الموظفين عالي الكثافة (Enterprise Table)**:
  - الأعمدة: اسم الموظف، المنصب، القسم، المسؤول المباشر، حالة الحساب (نشط/معطل)، ملخص الصلاحيات، الإجراءات (تعديل / كلمة المرور / الصلاحيات).
- **نافذة تخصيص الصلاحيات (Permission Matrix Modal)**:
  - مفاتيح اختيار واضحة لكل قسم ووظيفة:
    * العملاء: (حجب / قراءة فقط / تعديل وإضافة كاملة)
    * البرامج والتراخيص: (حجب / قراءة فقط / إدارة كاملة)
    * الدعم الفني والمشاكل: (حجب / قراءة فقط / معالجة وتعديل)
    * المتطلبات البرمجية: (حجب / قراءة فقط / إدارة وتحديث)
    * لوحة القيادة والتقارير: (حجب / إحصائيات عامة)
    * إدارة المهام: (عرض مهامي فقط / إسناد المهام للمرؤوسين)
- **بطاقات الأقسام والمسؤولين**:
  - عرض هيكل كل قسم، رئيس القسم (Chef de service)، وعدد الموظفين والمهام الجارية.

## 3. القرارات التقنية والمعمارية (Key Architecture & Trade-Offs)

### القرار 1: عزل المستأجرين (Multi-Tenancy Isolation Pattern)
- **الخيار المعتمد**: يتم تعريف كل شركة من خلال `companyId` (المرتبط بـ `uid` لمالك الشركة في Firebase Auth).
- **السبب**: يمنح أقصى درجات الأمان في Firestore؛ فكل الوثائق تكون تحت مسار `/companies/{companyId}/...`، مما يمنع منعاً باتاً تداخل بيانات الشركات أو اطلاع أي شركة على بيانات أخرى.

### القرار 2: مصادقة الموظفين داخل فضاء الشركة (Sub-Account Authentication)
- **الخيار المعتمد**: حفظ بيانات حسابات الموظفين وكلمات المرور المشفرة داخل مجموعة `employees` التابعة للشركة.
- **السبب**: يتيح للمدير إضافة موظفين فوريين دون مطالبتهم ببريد إلكتروني خارجي أو خطوات تفعيل خارجية، مع إمكانية إعادة تعيين كلمة مرور أي موظف فوراً بواسطة المدير.

## 4. المخطط المعماري واستراتيجية البيانات (Architecture & Data Strategy)

### هيكلية مجموعات Firestore (Database Collections)

```
firestore-root
│
├── companies/{companyId}                     [وثيقة تعريف الشركة والإعدادات]
│   │   name: "اسم المؤسسة"
│   │   ownerUid: "auth-uid-of-gerant"
│   │   ownerEmail: "owner@company.com"
│   │   createdAt: timestamp
│   │
│   ├── employees/{employeeId}               [حسابات الموظفين والصلاحيات]
│   │   fullName: "أحمد بن علي"
│   │   username: "ahmed_sales"
│   │   passwordHash: "hash"
│   │   jobTitle: "مسؤول مبيعات"
│   │   department: "القسم التجاري"
│   │   supervisorId: "gerant"
│   │   supervisorName: "المدير العام"
│   │   missions: ["متابعة العملاء", "إبرام العقود"]
│   │   permissions: { clients: "edit", programs: "view", ... }
│   │   isActive: true
│   │
│   ├── tasks/{taskId}                       [المهام المسندة لموظفي الأقسام]
│   │   title: "التواصل مع عملاء وهران"
│   │   department: "القسم التجاري"
│   │   assignedTo: employeeId
│   │   assignedBy: supervisorId
│   │   status: "قيد التنفيذ"
│   │   dueDate: "2026-10-20"
│   │
│   ├── clients/{clientId}                   [بيانات عملاء الشركة الخاصة بها]
│   │   programs/{programId}
│   │   issues/{issueId}
│   │   requirements/{reqId}
│   │   contacts/{contactId}
│
└── users/{userId}                           [سجل المستخدم المسجل]
```

### قواعد الأمان في Firestore (`firestore.rules`)
- تُمنح أذونات القراءة والكتابة الكاملة للشركة لمالكها الموثق (`request.auth.uid == companyId` أو مالك الفضاء).
- قواعد صارمة تمنع وصول أي مستخدم خارج الشركة إلى بياناتها.

## 5. خطة التنفيذ الميدانية المحدثة (Phased Implementation Plan)

1. **التهيئة المعمارية وتعدد الشركات (Multi-Tenant Engine)**:
   - تحديث `store.js` لدعم `currentCompany` و `currentEmployee` بجانب `currentUser`.
   - إزالة أي قيود ثابتة خاصة بحساب بعينه، وجعل تهيئة الفضاء ديناميكية لأي حساب شركة يسجل الدخول.
2. **تطوير قواعد أمان Firestore (`firestore.rules`)**:
   - إتاحة مسار عام للشركات والموظفين والمهام مع عزل صارم لكل مستأجر.
3. **تحديث شاشة تسجيل الدخول (`render-login.js`)**:
   - توفير مدخلين رئيسيين:
     * **دخول / إنشاء حساب شركة (Espace Entreprise / Gérant)**.
     * **دخول موظفي المؤسسة (Espace Collaborateur)** عبر اسم المستخدم وكلمة المرور.
4. **بناء واجهة إدارة الهيكل الوظيفي والموظفين (`render-employees.js`)**:
   - إضافة تبويب رئيسي في الشريط العلوي: **«الموظفون والأقسام»**.
   - لوحة إحصائيات الأقسام والكادر البشري.
   - جدول الموظفين وأزرار التحكم بالصلاحيات وإعادة تعيين كلمات المرور.
   - نافذة مودال متطورة لإضافة وتعديل الموظف ومصفوفة الصلاحيات.
5. **لوحة إسناد ومتابعة المهام (Task Workflow Engine)**:
   - إمكانية تكليف الموظف بمهام من قبل مسؤوله المباشر أو المدير، وتتبع حالات الإنجاز.
6. **إنفاذ الصلاحيات على سائر أقسام الـ CRM (`RBAC Enforcement`)**:
   - تطبيق دالة فحص الصلاحيات `canAccess(module, action)` على جميع النوافذ والأزرار والعمليات.
7. **الفحص والتحقق (`compile_applet`)**:
   - التأكد من سلامة بناء الكود وعدم وجود أي أخطاء برمجية.
